# Архитектурные решения (ADR-lite)

Формат: контекст → решение → альтернативы → последствия. Новые записи
добавляются в конец.

## D-001 · Flutter-проект в корне репозитория, бэкенд в `backend/` (2026-10-14)

- **Решение:** монорепозиторий; `lib/`, `ios/`, `android/` в корне,
  бэкенд появится в `backend/`.
- **Альтернативы:** `app/` + `backend/` — чище, но все Flutter-команды
  требуют `cd app`; отдельные репозитории — лишняя синхронизация контрактов.
- **Последствия:** Flutter-инструменты игнорируют `backend/`, Python-
  инструменты настраиваются из `backend/`.

## D-002 · Платформы: только iOS и Android (2026-10-14)

- Web/desktop не нужны продукту; меньше конфигурации и проверок.

## D-003 · Riverpod 3 без кодогенерации (2026-10-14)

- **Решение:** `flutter_riverpod` с ручными `Provider`/`FutureProvider`/
  `Notifier`, без `riverpod_generator`.
- **Почему:** меньше build_runner-шагов на старте; ручной стиль легко
  перевести на генератор позже.

## D-004 · Freezed/json_serializable пока не используются (2026-10-14)

- **Решение:** модели — обычные immutable-классы, sealed-классы Dart 3 для
  ошибок, ручной `toJson/fromJson` там, где нужно.
- **Почему:** моделей мало, кодогенерация добавляет шаг сборки и время
  компиляции. Пересмотреть, когда появятся DTO бэкенда (этап 4): тогда
  `json_serializable` может окупиться.

## D-005 · AI только на бэкенде; на клиенте `GenerationGateway` (2026-10-14)

- **Решение:** клиент не знает о провайдерах и не хранит ключей.
  `GenerationProvider` — серверная абстракция.
- **Последствия:** смена провайдера не требует релиза приложения.

## D-006 · Hosted API вместо собственного ML-pipeline (2026-10-14)

- См. docs/AI_PIPELINE.md §3. Собственный pipeline вводится по частям
  (remux звука, нарезка на сегменты) только на бэкенде.

## D-007 · «Free-first» порядок провайдеров (2026-10-14)

- **Контекст:** у автора нет бюджета на платные API.
- **Решение:** Mock → Hugging Face Space (бесплатная квота, только для
  экспериментов) → fal.ai (Wan Replace / Kling O3) после согласования
  бюджета.
- **Риск:** бесплатный путь нестабилен и не годится для релиза.

## D-008 · Минимальная серверная инфраструктура (2026-10-14)

- SQLite + локальный диск + asyncio-воркер вместо PostgreSQL + S3 + Redis.
  Все три скрыты за интерфейсами и заменяются при деплое/росте нагрузки.

## D-009 · Тёмная тема по умолчанию, единственная в MVP (2026-10-14)

- Видео лучше смотрится на тёмном фоне; токены позволяют добавить светлую
  тему без переписывания экранов.

## D-010 · Русский UI без l10n-инфраструктуры в MVP (2026-10-14)

- Строки пока прямо в виджетах. Перед выходом на другие рынки — перенос в
  ARB (`flutter_localizations`), задача R-04 в плане.

## D-011 · Liquid Glass как собственная реализация на BackdropFilter (2026-10-14)

- **Контекст:** автор хочет стиль iOS 26 Liquid Glass. Flutter рисует UI сам,
  поэтому системное стекло iOS к Flutter-виджетам не применяется; команда
  Flutter не планирует Liquid Glass в Cupertino (по сторонним источникам,
  официального анонса нет).
- **Решение:** свой компонент `GlassSurface` (`lib/core/widgets/glass/`):
  размытие + усиление насыщенности фона (`ImageFilter.compose`), градиентная
  заливка, блик по краю, суперэллипс (`RoundedSuperellipseBorder`), капсулы
  для кнопок. Под каждым экраном — анимированный `AmbientBackground`, иначе
  стеклу нечего преломлять. Плавающие элементы (`GlassScaffold`): кнопки
  сверху, главное действие внизу в зоне большого пальца.
- **Альтернативы:**
  - `liquid_glass_renderer` — настоящее преломление шейдером, но только
    dev-версии (0.2.0-dev.4, ноябрь 2025), помечен experimental, всплески
    памяти при анимации. Можно попробовать позже внутри `GlassSurface`
    только для отдельных элементов.
  - `liquid_glass_native` / `cupertino_native` — нативные iOS-контролы через
    platform views: стекло настоящее, но только iOS, ограниченный набор
    виджетов, проблемы со скроллом и производительностью.
- **Производительность:** карточки внутри контента используют
  `BackdropFilter.grouped` + `BackdropGroup` (общий снимок фона); плавающие
  элементы — обычный `BackdropFilter`, так как они лежат поверх другого стекла.
- **Доступность:** при «Уменьшить движение» фон не анимируется.
- **Риск:** нагрузка на GPU на слабых Android — проверить в P6-05.

## D-012 · Медиа-пакеты (2026-10-14)

- `image_picker` 1.2.4, `video_player` 2.14.1, `path_provider` 2.1.6 —
  официальные пакеты flutter.dev; `uuid` 4.6.0 (MIT);
  `fc_native_video_thumbnail` 3.0.1 (BSD-3, verified publisher, поддержка
  Flutter 3.44, SwiftPM) — превью видео.
- **Отклонены:** `video_thumbnail` (последний релиз 2025-05, ограничение
  SDK `<3.0.0`), `get_thumbnail_video` (2024-11, legacy darwin build),
  `file_picker` (системный медиапикер удобнее и не требует разрешений).
- Метаданные видео (длительность, размер) читаются через `video_player`:
  он поддерживает ровно те кодеки, которые устройство умеет проигрывать.
  Размер фото — из заголовка через `ui.ImageDescriptor`, без декодирования.

## D-013 · Хранение проектов: папка + JSON, относительные пути (2026-10-14)

- `Documents/projects/<id>/project.json` + `media/`. SQLite не нужен для
  десятков проектов; удаление проекта = удаление папки.
- Пути хранятся относительно Documents: на iOS абсолютный путь контейнера
  меняется после обновления приложения.
- Запись атомарная (tmp + rename); битый JSON пропускается, а не ломает
  весь список. `schemaVersion: 1` — задел для миграций.
- Медиа импортируются сразу в папку будущего проекта; если мастер закрыт
  без сохранения, папка удаляется при dispose черновика.

## D-014 · Минимальная iOS 14.0 (2026-10-14)

- Требование `fc_native_video_thumbnail`; заодно минимум для PHPicker
  (выбор фото без запроса доступа к галерее). Шаблон Flutter давал 13.0.

## D-015 · Лимиты медиа на клиенте (2026-10-14)

- Исходное видео 3–15 с и ≤200 МБ, фото ≥300×300 — под самый строгий из
  планируемых провайдеров (Kling O3 Edit). Видео-референс стиля 1–60 с.
- Фото пересжимаются пикером в JPEG ≤2048 px (заодно HEIC → JPEG).
- Длинные ролики — после появления нарезки на сегменты (P5-06).

## D-016 · Мастер создания: 4 шага, сохранение без генерации (2026-10-14)

- Видео + референсы → персонажи (ручное сопоставление «кого заменить»)
  → описание и параметры → проверка с согласием на права.
- Последний шаг честно сохраняет проект; кнопки «Запустить» нет, пока нет
  даже mock-генерации (этап 3).

## D-017 · Mock-генерация по времени, задачи переживают перезапуск (2026-10-14)

- `MockGenerationGateway` вычисляет статус по прошедшему времени от отправки
  (3 с загрузка, 3 с очередь, 14 с генерация) и хранит задачи в
  `Documents/mock/jobs.json`. Поэтому сценарий «свернул/закрыл приложение»
  ведёт себя как с настоящим сервером.
- «Результат» — исходное видео пользователя, всегда `isSynthetic = true`;
  UI показывает «Тестовый результат, не AI» и пояснение. Никакой
  псевдо-обработки (фильтров) не делаем, чтобы не создавать впечатление AI.
- Сбой демонстрируется переключателем в Настройках (только демо-режим).
- Время — через пакет `clock`, таймеры — `Timer`: в тестах всё ускоряется
  через `fake_async`.

## D-018 · Отслеживание задачи (2026-10-14)

- `GenerationService` — запуск/обновление/отмена и запись статуса в проект
  (`lastJobId`, `lastJobStatus`, `lastFailureMessage`, `resultRelativePath`,
  `resultIsSynthetic`).
- `JobTracker` (autoDispose family по projectId) опрашивает раз в 1 с, пока
  экран показывает проект; при `NetworkFailure` — повтор с экспоненциальной
  паузой до 10 с; другие ошибки останавливают опрос и показываются.
- Пока приложение закрыто, опроса нет; при открытии проекта/главного экрана
  задача продолжает отслеживаться по сохранённому id. Push-уведомления —
  после бэкенда.
- Режим `GENERATION_MODE=backend` пока честно отвечает «Сервер обработки ещё
  не подключён».

## D-019 · Экран результата: крупное превью + список под ним (2026-10-14)

- Превью не уменьшается; бейдж, пояснение, запрос и примечания идут
  обычным прокручиваемым списком под видео, кнопка «Сгенерировать ещё раз»
  плавает внизу, как на остальных экранах.
- Выдвижной лист (`DraggableScrollableSheet`) пробовали и убрали: автор
  имел в виду список, а модальный лист выбивался из стиля приложения.
